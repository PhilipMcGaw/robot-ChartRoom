===== Summary =====

Daniel Eichhorn's 2018 ''ESP8266 Weather Station: Getting Started Guide'' walks through a NodeMCU ESP8266 station with an organic light-emitting diode (OLED) display, an internet weather-data service, and a separate climate node. The climate node reads a digital humidity and temperature (DHT) sensor and sends data to a ThingSpeak channel; the display station can retrieve those readings alongside online weather information. This is a historical example of separating a remote sensor node from a display and data service.

===== Relevance and limitations =====

The pattern may be useful when comparing sensor-node and gateway arrangements. Its reliance on internet services means it does not demonstrate offline-first buoy operation, local durable buffering during outages, or a radio link between field nodes and a gateway. The guide is tied to older ESP8266 software libraries and external service APIs, so it is background material rather than a current implementation procedure. It provides no evidence of instrument calibration, outdoor environmental qualification, or low-power operation.

The supplied copy contains example service configuration values. They have not been copied into Chartroom; never reuse credentials or API keys from sample code.
