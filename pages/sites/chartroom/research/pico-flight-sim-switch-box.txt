===== Scope =====

This note summarises Hackster.io's report on a custom flight-simulator switch box built by DarkfullDante. The Hackster report links to the builder's Reddit post for additional details. This is a desktop gaming control, not a flight-control system for a real aircraft or robot.

===== Reported design =====

The report describes a Raspberry Pi Pico running CircuitPython and presenting controls to a computer through a combination of USB Human Interface Device (HID) gamepad and keyboard inputs. The builder used physical switches, a rotary encoder, and linear potentiometers in a stock aluminium enclosure. The builder said some controls were salvaged from an old television amplifier.

The article explains that the builder used keyboard function keys F13–F24 for rotary-encoder actions because the gamepad interface did not provide enough buttons for the desired nine-position selector behaviour. This is a reported workaround for that build and software environment, not a general requirement for CircuitPython controllers.

The article says the box was intended for Microsoft Flight Simulator and Elite Dangerous. The linked Reddit post contains additional discussion and interior photographs.

===== Relevance =====

This is a reference for a low-cost, custom operator input panel using a microcontroller as a USB gamepad and keyboard. The input mapping approach may be useful when considering physical control panels, test fixtures, or simulator controls. It does not establish compatibility with Cockpit, BlueOS, ArduPilot, or any project robot.

===== Limitations =====

The available sources are a Hackster article and the builder's Reddit post. They do not provide a complete tested bill of materials, full source code, measured latency, or evidence of compatibility beyond the stated desktop games. The article's note about a future 64-bit gamepad protocol reflects the state described at publication and should not be treated as a current CircuitPython capability statement.
