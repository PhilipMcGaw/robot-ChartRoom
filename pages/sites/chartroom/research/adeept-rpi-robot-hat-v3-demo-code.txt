===== Source and reuse =====

Adeept's [[https://github.com/adeept/Adeept_Robot_HAT-V3|official Robot HAT V3 repository]] contains examples numbered 01 to 13. The source headers identify Adeept as author and give the date as 2025-04-02. The user reports that Adeept authorised redistribution of examples 02 to 13 in Chartroom on 2026-11-17. ''01_Servo.py'' contains an MIT identifier inside its source docstring. Unmodified copies of examples 01 to 13 are in the repository's [[https://github.com/PhilipMcGaw/robot-ChartRoom/tree/main/examples/adeept-rpi-robot-hat-v3|Adeept Robot HAT V3 example folder]].

The user's [[https://philipmcgaw.com/adeept-robot-hat-for-raspberry-pi/|Adeept Robot HAT for Raspberry Pi post]] documents using ''01_Servo.py'' on servo channel 0. An archived copy is included for completeness. Adeept's supplied ''setup.py'' is archived with the examples as a reference, but has not been run. It invokes privileged system and global Python package installations; review the file before any use.

The examples have been inspected as source only; none was run as part of this review. They were written for the Adeept Robot HAT V3. Confirm that their GPIO, I²C, SPI, and peripheral assumptions match the fitted HAT revision before testing. The HAT in use is identified as V3.1, but the supplied schematic revision has not yet been matched to the physical board.

===== PyInfra setup pilot =====

The example folder includes ''pyinfra/deploy.py'', a focused PyInfra deployment for a Raspberry Pi OS host. It follows the user's [[https://philipmcgaw.com/my-basic-linux-setup/|basic Linux setup preferences]]: update and upgrade APT packages, remove unused dependencies, install ''git'', ''nano'', and Zsh, use Oh My Zsh with the ''clean'' theme, and show Hyfetch at interactive login. These shell settings apply to the account used for the SSH connection. The user's separate [[https://philipmcgaw.com/passwordless-sudo/|passwordless sudo post]] configures an Ubuntu virtual machine; the basic setup post reports passwordless sudo is already present on Raspberry Pi OS, so the deployment leaves sudoers unchanged. It does not copy the SSH public key shown in the post or change SSH authentication.

The deployment also installs ''openssh-server'' and ensures ''ssh.service'' is running and enabled. It enables I²C and SPI by adding a managed block to ''/boot/firmware/config.txt'', or ''/boot/config.txt'' on older images; it creates a dated backup before changing the file. It installs APT packages for GPIO, I²C, SPI, Pillow, and NumPy; creates a virtual environment under ''/opt/adeept-rpi-robot-hat-v3/.venv'' with access to those system packages; installs Adafruit Blinka and the example-specific Adafruit and MPU-6050 packages; and copies examples 01 to 13 to ''/opt/adeept-rpi-robot-hat-v3/''.

Run PyInfra from an administration computer over SSH. This deployment can maintain an already reachable SSH server, but it cannot bootstrap remote access when SSH is disabled; use Raspberry Pi Imager or local access for first-time setup. Review with the ''--dry'' option before applying. The interface changes and any required OS upgrade reboot take effect after a manual reboot; the deployment leaves rebooting to the operator. It does not change SSH authentication settings or firewall rules, enrol an SSH key, edit sudoers, execute Adeept's ''setup.py'' or any example, or check the board's power path. Its dependencies and operation have not been verified on the target Pi. This is a narrow setup pilot, not a decision to adopt PyInfra for project-wide provisioning. See the example folder's ''pyinfra/README.md'' for commands and limitations.

===== D1 and bench-test sequence =====

The code examples do not test D1. Check the reported SS34 fault and the board's power path before powering the HAT for software tests. A diode-mode reading on an unpowered board can be affected by other components, so confirm the D1 orientation and circuit against the supplied schematic and fitted board revision. Do not treat a successful example as evidence that D1 is healthy.

After the power path is understood, test one example at a time. Start with sensor readouts whose matching modules are connected, then test the indicator outputs. Test moving outputs last: use one unloaded servo for ''01_Servo.py'', and secure the robot with its wheels clear before running ''05_Motor.py''. Record the fitted revision, supply, connected loads, and observations as bench-test evidence; none is recorded yet.
