===== Source and reuse =====

Adeept's [[https://github.com/adeept/Adeept_Robot_HAT-V3|official Robot HAT V3 repository]] contains examples numbered 01 to 13. The source headers identify Adeept as author and give the date as 2025-04-02. The user reports that Adeept authorised redistribution of examples 02 to 13 in Chartroom on 2026-11-17. Unmodified copies of those files are in the repository's [[https://github.com/PhilipMcGaw/robot-ChartRoom/tree/main/examples/adeept-rpi-robot-hat-v3|Adeept Robot HAT V3 example folder]].

The user's [[https://philipmcgaw.com/adeept-robot-hat-for-raspberry-pi/|Adeept Robot HAT for Raspberry Pi post]] documents using ''01_Servo.py'' on servo channel 0. That source is not duplicated in the example folder. Adeept's supplied ''setup.py'' is also not included: it runs package-manager installation commands with ''sudo'', installs Python packages globally, and uses ''--break-system-packages'' on newer Debian releases. It has not been run.

The examples have been inspected as source only; none was run as part of this review. They were written for the Adeept Robot HAT V3. Confirm that their GPIO, I²C, SPI, and peripheral assumptions match the fitted HAT revision before testing. The HAT in use is identified as V3.1, but the supplied schematic revision has not yet been matched to the physical board.

===== D1 and bench-test sequence =====

The code examples do not test D1. Check the reported SS34 fault and the board's power path before powering the HAT for software tests. A diode-mode reading on an unpowered board can be affected by other components, so confirm the D1 orientation and circuit against the supplied schematic and fitted board revision. Do not treat a successful example as evidence that D1 is healthy.

After the power path is understood, test one example at a time. Start with sensor readouts whose matching modules are connected, then test the indicator outputs. Test moving outputs last: use one unloaded servo for ''01_Servo.py'', and secure the robot with its wheels clear before running ''05_Motor.py''. Record the fitted revision, supply, connected loads, and observations as bench-test evidence; none is recorded yet.
