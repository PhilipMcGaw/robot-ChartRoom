===== Project summary =====

The article connects an Arduino Uno to an MPU-6050 over I²C and sends three orientation values over serial to a Processing program. The Processing sketch draws an artificial horizon, pitch and bank scales, and a compass-like circular display. The author identifies the MPU6050 MotionApps 6-axis library and uses its digital motion processor output for yaw, pitch, and roll. The code selects a serial port and uses a baud rate of 115,200.

===== Compass terminology and limitations =====

Despite the article's title and display label, the MPU-6050 contains a three-axis accelerometer and a three-axis gyroscope; it has no magnetometer. The displayed azimuth comes from the yaw value calculated from the motion processor's orientation quaternion. It is therefore not a magnetic-compass measurement or an absolute heading reference. With no external heading reference, yaw derived from inertial sensing can drift over time.

The page is a useful demonstration of transporting orientation values from a microcontroller to a desktop visualisation. It does not document quantitative accuracy, calibration results, drift, update latency, or testing during sustained motion. Its displayed scaling and graphics should not be treated as a validated instrument or an autopilot attitude estimate.

===== Relevance and limits =====

This is a historical example for a lightweight sensor-to-visualisation path and an operator-facing attitude display. It may inform experiments with serial telemetry and visual presentation, but it does not validate an inertial measurement unit (IMU) choice or sensor-fusion method for a vehicle. For an experimental multi-sensor board reference, see [[sites:chartroom:research:gy-91-mpu9250-assessment|GY-91 MPU-9250/9255 IMU assessment]]. That assessment also explains why a magnetometer's heading must be checked in the assembled vehicle environment.
