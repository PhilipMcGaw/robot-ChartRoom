# Documentation and technical communication design

This page collects research and design references for writing clear technical information across the Robots ecosystem, including classroom material, project documentation, datasheets, presentations, and public-facing technical communication.

## Raspberry Pi Foundation — Mayer's Principles

**Reference:** [How to design and present clear computing lessons](https://www.raspberrypi.org/blog/how-to-design-and-present-clear-computing-lessons-mayers-principles/)

**Quick Reads:** [Designing Multimedia for Clarity](https://static.raspberrypi.org/files/curriculum/quickreads/QR32_Mayers_Principles_1_17_04_2026.pdf) and [Raspberry Pi Foundation Quick Reads](https://www.raspberrypi.org/teach/pedagogy/quick-reads)

Mayer's Principles of Multimedia Learning provide a useful framework for reducing unnecessary cognitive load. Although the source is aimed at computing education, the principles are applicable to technical communication more generally.

### Principles worth applying

- **Coherence:** include information that directly supports the purpose; remove decorative or tangential material.
- **Signalling:** deliberately guide attention using headings, emphasis, arrows, colour, cursor movement, or other cues.
- **Redundancy:** avoid presenting identical information in several forms when doing so adds load rather than clarity.
- **Spatial contiguity:** keep labels, explanations, and the visuals they describe close together.
- **Temporal contiguity:** align related explanations and visuals in time when presenting dynamic material.
- **Segmenting:** break complex material into manageable stages rather than presenting the complete system at once.
- **Pre-training:** introduce important terms, components, and relationships before asking the reader to understand a more complex model.
- **Modality:** where appropriate, use spoken explanation alongside diagrams, demonstrations, or code rather than filling visual material with dense explanatory text.

### Application to the Robots ecosystem

Use these principles as a review checklist when producing:

- classroom and ROS 2 learning material;
- engineering design and build documentation;
- datasheets and interface specifications;
- project READMEs and onboarding material;
- presentations and demonstrations;
- press releases and project announcements; and
- diagrams, architecture documents, and UI documentation.

The goal is not to make every document look like a lesson. Instead, use the principles to choose the right information density, sequence, visual structure, and level of explanation for the intended audience.

A useful distinction is:

> **Technical accuracy is necessary, but presentation determines how easily that accuracy can be understood and used.**
